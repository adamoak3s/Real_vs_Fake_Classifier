Task 4: Regularization study¶

Objective: increase validation accuracy (if possible) with regularization techniques (batch normalization, dropout, L2 weight decay) and report how each one affects validation accuracy.

Adam Oakes

Setup: Task 3's best pipeline is the new baseline

  • Same CNN as the Task 2 best model (5 conv blocks, 32→512 filters, GAP, sigmoid), with horizontal-flip augmentation, the best pipeline from Task 3 (0.9507 validation accuracy). Every regularizer below is added on top of that pipeline.
  • Same optimizer (Adam) and batch size (64). Each model trains for up to 20 epochs; early stopping ends a run after 3 epochs without a new best validation accuracy and restores the best epoch's weights. Task 3 showed the model only starts to overfit after about 10 epochs, and regularization only has something to fix once it does.
  • Every configuration trains a fresh model from the same random seed, so the only thing that changes between rows of the results table is the regularization.
  • The baseline (flip, no regularization) is trained twice with two different seeds. The gap between those two runs is the noise floor.
  • Images load at their native 32×32 and are cached in memory; the flip and the 32→180 upsample happen inside the model on the GPU.

The three techniques, and what each one actually does

  • Dropout randomly zeroes a fraction of activations at every training step. No single unit can be relied on, so the network has to spread information out. It is off at inference. It is tested in two places: on the 512 pooled features right before the classifier ("head"), and after every conv block ("conv").
  • L2 regularization adds λ·Σw² to the loss, which pulls every weight toward zero unless the data keeps pushing it away. It is applied to every conv and dense kernel.
  • Batch normalization re-centers and re-scales each channel's activations using the statistics of the current batch. It is mainly an optimization aid that lets training move faster and more stably. The regularizing effect is a side effect: each image's output depends slightly on which other images share its batch, which adds noise.

FILTERS = [32, 64, 128, 256, 512]

def build_model(reg, name):
    bn = reg.get("bn", False)
    l2 = reg.get("l2", 0.0)
    kreg = regularizers.L2(l2) if l2 else None
    inputs = keras.Input(shape=NATIVE_SIZE + (3,))
    x = inputs
    for make in AUGMENTATION:                 # Task 3's best pipeline; active only during training
        x = make()(x)
    x = layers.Resizing(*MODEL_SIZE, interpolation="bilinear")(x)   # same 32->180 upsample as Task 2
    x = layers.Rescaling(1.0 / 255)(x)
    for i, f in enumerate(FILTERS):
        if bn:
            # BN has its own shift (beta), so the conv bias is redundant
            x = layers.Conv2D(f, 3, use_bias=False, kernel_regularizer=kreg)(x)
            x = layers.BatchNormalization()(x)
            x = layers.Activation("relu")(x)
        else:
            x = layers.Conv2D(f, 3, activation="relu", kernel_regularizer=kreg)(x)
        if i < len(FILTERS) - 1:              # last block has no pool, same as Task 2
            x = layers.MaxPooling2D(2)(x)
            if reg.get("conv_dropout"):
                x = layers.Dropout(reg["conv_dropout"])(x)
    x = layers.GlobalAveragePooling2D()(x)
    if reg.get("head_dropout"):
        x = layers.Dropout(reg["head_dropout"])(x)
    outputs = layers.Dense(1, activation="sigmoid", kernel_regularizer=kreg)(x)
    model = keras.Model(inputs, outputs, name=name.replace(".", "p").replace("+", "_"))
    model.compile(loss="binary_crossentropy", optimizer="adam", metrics=["accuracy"])
    return model

def describe(reg):
    if not reg:
        return "-"
    parts = []
    if reg.get("bn"): parts.append("BatchNorm after every conv")
    if reg.get("conv_dropout"): parts.append(f"Dropout({reg['conv_dropout']}) after every pool")
    if reg.get("head_dropout"): parts.append(f"Dropout({reg['head_dropout']}) before Dense")
    if reg.get("l2"): parts.append(f"L2({reg['l2']:g}) on all kernels")
    return "; ".join(parts)

Run the sweep¶

The results go to a CSV after every configuration. If the kernel dies or you stop it, re-running this cell skips the configurations that already finished. To start over, delete the CSV named in the output of the configuration cell.

Expect about 35–40 s per epoch on the GPU (BatchNorm is a little slower), and roughly 10–15 epochs per configuration before early stopping, so about 1.5–2 hours for the whole sweep.

Use accuracy, not loss, to compare rows. With L2 turned on, Keras adds the penalty λ·Σw² to both the training loss and the validation loss it reports, so an L2 run's loss is partly measuring the weights, not the predictions. Accuracy is the one number that means the same thing in every row.

def load_results():
    return pd.read_csv(RESULTS_CSV) if RESULTS_CSV.exists() else pd.DataFrame()

def load_histories():
    return json.loads(HISTORY_JSON.read_text()) if HISTORY_JSON.exists() else {}

def run_config(name, family, reg, seed=SEED):
    done = load_results()
    if len(done) and name in set(done["config"]):
        print(f"skip {name} (already done)")
        return
    keras.backend.clear_session()   # free the previous model's GPU memory before building the next one
    gc.collect()
    keras.utils.set_random_seed(seed)
    model = build_model(reg, name)
    cb = [keras.callbacks.EarlyStopping(monitor="val_accuracy", patience=PATIENCE,
                                        mode="max", restore_best_weights=True)]
    t0 = time.time()
    h = model.fit(train_ds, epochs=EPOCHS, validation_data=val_ds, callbacks=cb, verbose=2)
    secs = time.time() - t0
    hist = {k: [float(v) for v in vals] for k, vals in h.history.items()}
    best = int(np.argmax(hist["val_accuracy"]))
    row = dict(
        config=name, family=family, description=describe(reg), reg=json.dumps(reg), seed=seed,
        params=model.count_params(),
        best_val_acc=hist["val_accuracy"][best], best_epoch=best + 1,
        final_val_acc=hist["val_accuracy"][-1],
        final_train_acc=hist["accuracy"][-1],
        sec_per_epoch=secs / len(hist["accuracy"]),
    )
    pd.concat([done, pd.DataFrame([row])], ignore_index=True).to_csv(RESULTS_CSV, index=False)
    hs = load_histories(); hs[name] = hist
    HISTORY_JSON.write_text(json.dumps(hs))
    print(f"==> {name}: best val_acc {row['best_val_acc']:.4f} (epoch {row['best_epoch']})")

for name, (family, reg) in CONFIGS.items():
    seed = SECOND_SEED if name.startswith("baseline_seed") else SEED
    run_config(name, family, reg, seed=seed)

Discussion¶

The baseline (Task 3's best pipeline: the Task 2 CNN with horizontal flip) reached 0.9428; its second-seed run reached 0.9473, so differences under about 0.5 points are within run-to-run noise. (The same pipeline scored 0.9507 in Task 3 on the same machine: GPU training is not exactly repeatable, so identical runs can differ by up to about 0.8 points.)

Dropout before the classifier was the only clear improvement: 0.9505 (+0.8) at rate 0.5 and 0.9495 (+0.7) at 0.25. It did not raise the peak much. It delayed overfitting: the baseline peaked around epoch 10 and then declined, while with dropout 0.5 validation accuracy stayed near 0.95 through epoch 20.

BatchNorm made training much faster but did not end meaningfully higher (+0.5, barely above the noise threshold), and its validation accuracy was unstable. L2 hurt at 1e-4 and 1e-3; at 1e-3 the model underfit (training and validation accuracy both stalled near 0.90). Dropout after every conv block was effectively neutral at 0.1 and hurt at 0.25. Combining techniques did not help: BatchNorm + L2 was unstable (−2.4), and the automatic best-of combination scored −0.3.

Caveats: one seed per configuration, and early stopping (patience 3) cut some runs short, notably L2 1e-4. Dropout's +0.8 is at the edge of the run-to-run noise, so the evidence that it helps rests mainly on the training curves (it delayed overfitting), not on the size of the gain.
